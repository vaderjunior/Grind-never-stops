# P2 — Rate limiter

An atomic bucket admits at most its starting capacity plus elapsed refill; regional reservations never exceed the global allocation.

This prepared teaching lab uses Python 3.11+ standard-library modules. It is separate from the academy learner database. Read [the shared lab instructions](README.md) before running commands. Reference tests have been executed; learner TODOs are intentional work.

## Requirements and mechanism

- Implement deterministic token-bucket boundaries with explicit capacity, refill rate, clock, and request cost.
- Serialize shared read/refill/debit using SQLite BEGIN IMMEDIATE. Preserve per-tenant isolation.
- Choose fail-open or fail-closed explicitly; report degraded decisions. Regional quotas are disjoint reservations rather than a fictional global counter.

tenant request → validation → atomic bucket refill/debit → allowed or retry_after. Regional design allocates conserved token ceilings before a partition occurs.

**Limits:** SQLite is one shared authority on one machine. Regional allocation is a static accounting model. Dynamic quota transfer, distributed clocks and an HTTP proxy are extensions.
