# P5 — Event pipeline

Each accepted event has a stable ID and immutable payload. A projection update, deduplication marker, and checkpoint advance commit atomically within the teaching database.

This prepared teaching lab uses Python 3.11+ standard-library modules. It is separate from the academy learner database. Read [the shared lab instructions](README.md) before running commands. Reference tests have been executed; learner TODOs are intentional work.

## Requirements and mechanism

- Partition events deterministically by account and order ingestion offsets within each partition.
- Apply additive minor-unit deltas correctly even when event-time order differs from arrival order.
- Recover checkpoints, rebuild a separate projection, upcast supported schema versions, and reconcile against the immutable source.

validated event → immutable partitioned SQL log → bounded consumer batch → atomic applied-ID + account total + checkpoint; replay writes a named shadow projection.

**Limits:** All log/projection state is in one SQLite authority. The transaction is not a promise of exactly-once external effects or a distributed stream processor. Late-event semantics here are additive totals, not event-time windows.

## Milestone 1 · Lesson 109 · Partitioned ingestion and replayable identity

Source activity: [P5.1] Event pipeline: partitioned ingestion and replayable consumers

Use SHA-256 of account to choose a fixed partition count. Assign increasing offsets transactionally. Repeat the same event ID and payload to obtain the original offset; reject a changed payload. Persist the partition count as immutable configuration.

**Failure injection:** Changing partition count in place can reorder an account and invalidate existing checkpoints. Require a migration instead of silently rehashing a durable log.

**Acceptance evidence:** Show stable account affinity, increasing offsets, and duplicate ingest returning the original position.

## Milestone 2 · Lesson 119 · Projection, duplicate and late-event behavior

Source activity: [P5.2] Event pipeline: projections, duplicate handling, and late-event tests

Maintain integer account totals. An event with an earlier event_time still changes the total once when it arrives. Store a deduplication marker and advance the partition checkpoint in the same transaction as the total.

**Failure injection:** A checkpoint committed ahead of a projection loses work; projection committed without dedupe can double-apply retries. Keep the transaction boundary explicit.

**Acceptance evidence:** Apply +10 at time 200 and −3 at time 100, consume twice, and reconcile to exactly 7.

## Milestone 3 · Lesson 238 · Crash recovery and safe replay

Source activity: [P5.3] Event pipeline: checkpoint recovery, batch replay, and reconciliation

Inject a failure after a projection write but before checkpoint persistence. Verify rollback, reopen the database, and consume again. Build a named shadow projection with its own checkpoints, leaving live data available.

**Failure injection:** Rebuilding live state by deleting it first creates an avoidable outage and makes validation difficult. Compare the completed shadow projection before any future cutover.

**Acceptance evidence:** Show zero partial projection after the injected failure, correct recovery, and a successful independent replay reconciliation.

## Milestone 4 · Lesson 239 · Schema and backfill evidence

Source activity: [P5.4] Event pipeline: schema/backfill failure tests and evidence report

Accept v1 amount and v2 amount_minor_units as explicit schemas with integer money units. Reject unknown versions and same-ID payload conflicts. Recompute expected account sums from source events and compare derived totals.

**Failure injection:** A guessed default for an unknown schema can silently corrupt totals. Quarantine unsupported inputs upstream and make failure visible instead of treating them as zero.

**Acceptance evidence:** Mix two supported versions, reject a future version, and report expected versus actual totals. Document the rollback condition for a shadow projection cutover.
