# P6 — AI inference gateway

Admission atomically reserves each tenant’s maximum output-unit budget before work starts. Completion, cancellation and failure release unused reservations and preserve per-request accounting.

This prepared teaching lab uses Python 3.11+ standard-library modules. It is separate from the academy learner database. Read [the shared lab instructions](README.md) before running commands. Reference tests have been executed; learner TODOs are intentional work.

## Requirements and mechanism

- Expose a bounded streaming generator backed by an explicit local deterministic token stub.
- Isolate tenant concurrency and output-unit budgets; reject reused request IDs rather than silently double-charge or replay incomplete streams.
- Record delivery-unit counts, time to first delivered token, duration, and outcome; release reservations on every terminal path.

tenant + request ID → atomic concurrency/budget reservation → cancellable stub iterator → delivered token stream → finally release unused units + telemetry.

**Limits:** No AI model runs here. Stub tokens are illustrative output units, not tokenizer IDs, provider billing or measured inference throughput. Budgets are process-local. Deadline checks occur between cooperative stub tokens and cannot interrupt an arbitrary blocking provider call; real adapters need cancellable I/O and provider-side billing reconciliation.
